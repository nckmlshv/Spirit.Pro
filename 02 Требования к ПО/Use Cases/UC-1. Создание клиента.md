# UC-1. Создание нового клиента

| UC-1 | Создание нового клиента |
|---|---|
| **Акторы** | **1.** Администратор-консультант (АК/СТАК)<br>**2.** Клиент |
| **Предусловия** | **1.** АК авторизован в системе<br>**2.** Клиент находится на ресепшен<br>**3.** Клиент предъявил оригинал документа, удостоверяющего личность |
| **Триггер** | **1.** АК нажимает «Поиск клиента» на Главной странице. |
| **Основной поток** | **1.** Система открывает форму поиска клиента.<br>**2.** АК выполняет поиск по одному из реквизитов: номер телефона, ФИО, ДУЛ, электронная почта или браслет.<br>**3.** Система не находит клиента и предлагает создать нового.<br>**4.** АК подтверждает создание.<br>**5.** Система открывает карточку «Основная информация», автоматически заполнив поле, по которому выполнялся поиск.<br>**6.** АК заполняет персональные данные клиента с оригинала документа.<br>**7.** Система выполняет проверку на дубли по номеру телефона, ДУЛ и по комбинации «Дата рождения + Имя + Отчество».<br>**8.** Совпадений не найдено, система формирует документы для подписания — согласие на обработку персональных данных с блоком данных клиента для сверки и согласие на получение рекламных материалов, каждый со штрихкодом — и отправляет на печать.<br>**9.** Клиент проверяет напечатанные данные и подписывает документы.<br>**10.** АК нажимает «Создать клиента».<br>**11.** Система создаёт запись клиента в статусе ПЧК и открывает его карточку. |
| **Постусловие** | **1.** Клиент создан в системе со статусом ПЧК.<br>**2.** Согласия подписаны.<br>**3.** АК находится в карточке клиента и может продолжить обслуживание.<br>**4.** Операция зафиксирована в журнале изменений. |
| **Исключения** | **6.1** Клиент несовершеннолетний — система отмечает необходимость согласия законного представителя и включает соответствующий блок в печатные документы. АК заводит карточку законного представителя и привязывает к ней несовершеннолетнего клиента.<br>**6.2** Клиент отказывается предоставить паспортные данные — создание невозможно, оформление прекращается.<br>**6.3** Клиент отказывается от согласия на рекламные материалы — отметка об отказе фиксируется в карточке.<br>**6.4** Клиент отказывается от согласия на обработку персональных данных — создание клиента невозможно, оформление прекращается.<br>**7.1** Найдена карточка с идентичным номером ДУЛ — система блокирует создание, АК переходит в существующую карточку.<br>**7.2** Найдена карточка с идентичным номером телефона — система блокирует создание и открывает найденную карточку.<br>**7.3** При поиске по ФИО и дате рождения система находит несколько карточек, - АК сверяет другие данные клиента (телефон, ДУЛ) и выбирает нужную карточку. Если нужной нет, - создает новую.<br>**9.1** Клиент обнаружил ошибку в напечатанных данных — АК исправляет данные в системе, документы формируются и печатаются заново. |
| **Связанные требования** | **ФТ-06** Система должна обеспечивать поиск клиента по номеру телефона, ФИО, номеру ДУЛ, электронной почте и браслету.<br>**ФТ-07** Система должна исключать создание дублирующих карточек клиентов и предупреждать администратора о вероятных совпадениях с существующими записями.<br>**ФТ-08** Система должна вести историю документов клиента с сохранением ранее действовавших ДУЛ.<br>**ФТ-09** Система должна формировать печатные документы со штрихкодом для последующей автоматической привязки скана к карточке клиента.<br>**ФТ-10** Система должна обеспечивать привязку несовершеннолетнего клиента к карточке законного представителя. |
