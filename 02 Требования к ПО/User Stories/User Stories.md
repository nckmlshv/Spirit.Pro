# User Stories

## Администратор-консультант (АК)

### US-01. Оформление контракта в одном сценарии

**Как** АК, **я хочу** оформлять контракт без переключения между разделами, **чтобы** не заставлять клиента ждать и не терять данные между экранами.

**Acceptance criteria:**
- Все шаги оформления выполняются в рамках одного экрана
- Отображаются только тарифы, доступные клиенту по возрасту, статусу и наличию действующих контрактов
- Данные клиента подставляются из карточки автоматически
- При наличии действующего контракта система показывает предупреждение о бесшовной активации нового

### US-02. Скрипт разговора с клиентом

**Как** АК, **я хочу** видеть подсказку о том, что важно озвучить клиенту по выбранному тарифу, **чтобы** ничего не упустить и не держать условия в голове.

**Acceptance criteria:**
- Скрипт отображается на экране условий выбранного тарифа
- Скрипт содержит формулировки для разговора, а не текст условий договора
- При отклонениях от типового сценария отображается дополнительный блок подсказок
- Скрипт доступен без перехода в другой раздел

### US-03. Автоматическая привязка сканов

**Как** АК, **я хочу** сканировать документы пачкой в конце дня, **чтобы** они сразу прикреплялиськ карточкам соответствующих клиентов.

**Acceptance criteria:**
- Печатный документ содержит штрихкод, связанный с клиентом и типом документа
- Отсканированный документ привязывается к карточке клиента автоматически
- Привязка выполняется без участия администратора после сканирования
- Привязанный документ отображается в карточке клиента с датой и типом

### US-05. Продуктовая витрина клиента

**Как** АК, **я хочу** видеть, что можно предложить конкретному клиенту, **чтобы** не угадывать потребность и продавать чаще.

**Acceptance criteria:**
- Перечень предложений формируется с учётом тарифа, истории посещений и статуса в программе лояльности
- Предложения отображаются в карточке клиента без дополнительного запроса
- По каждому предложению доступен переход к оформлению
- Недоступные клиенту предложения не отображаются

## Старший администратор-консультант (СТАК)

### US-06. Единый контур заявок

**Как** СТАК, **я хочу** создавать заявки в смежные подразделения из системы, **чтобы** не координировать работу через звонки и мессенджеры.

**Acceptance criteria:**
- Заявка создаётся с указанием подразделения-исполнителя и описания
- Статус заявки отображается в системе на всех этапах исполнения
- При изменении статуса автор заявки получает уведомление
- Заявки клуба отображаются единым списком с фильтрацией по статусу и подразделению

### US-07. Маршрутизация обращений

**Как** СТАК, **я хочу** переводить обращения клиентов на смежные подразделения, **чтобы** вопрос решался профильными сотрудниками с сохранением истории.

**Acceptance criteria:**
- Обращение переводится на другое подразделение без создания новой записи
- История переписки и вложений сохраняется при переводе
- Отображается текущий исполнитель обращения
- Все переводы фиксируются с указанием автора и времени

### US-08. Контроль незакрытых операций

**Как** СТАК, **я хочу** видеть неоплаченные контракты администраторов смены, **чтобы** возвращаться к ним до истечения срока ссылки.

**Acceptance criteria:**
- Отображается список контрактов в статусе ожидания оплаты с указанием администратора
- По каждой операции видно время до истечения платёжной ссылки
- Список фильтруется по администратору и дате
- Из списка доступен переход в карточку клиента

### US-09. Внутренние задачи клуба

**Как** СТАК, **я хочу** ставить и отслеживать задачи по внутренним процессам, **чтобы** поручения не терялись между сменами.

**Acceptance criteria:**
- Задача создаётся с указанием исполнителя, срока и описания
- Задачи отображаются списком с фильтрацией по статусу и исполнителю
- При приближении срока исполнитель получает уведомление
- Незакрытые задачи видны следующей смене

### US-10. Личная эффективность

**Как** СТАК, **я хочу** видеть свои показатели и результаты проверок тайных покупателей, **чтобы** влиять на них до подведения итогов периода.

**Acceptance criteria:**
- Отображаются личные показатели продаж и конверсии за период
- Результаты проверок тайных покупателей доступны сразу после публикации
- Показатели отображаются в динамике
- Доступно сравнение с показателями клуба

## Управляющий клубом (УК)

### US-12. Показатели клубов в одном окне

**Как** УК, **я хочу** видеть показатели своих клубов на одном экране, **чтобы** не сводить данные вручную в таблице.

**Acceptance criteria:**
- Показатели всех подведомственных клубов отображаются в едином представлении
- Доступно сравнение клубов между собой по выбранному показателю
- Отображаются план, факт и динамика к предыдущему периоду
- Данные соответствуют операционным данным системы без ручной сверки

### US-13. Уведомления о критичных событиях

**Как** УК, **я хочу** получать уведомления о критичных событиях, **чтобы** узнавать о проблемах сразу, а не при следующем заходе в отчёт.

**Acceptance criteria:**
- Уведомления приходят по заданным событиям без запроса со стороны управляющего
- Уведомление содержит суть события и ссылку на связанный объект
- Перечень событий для уведомления настраивается
- История уведомлений сохраняется

### US-14. Формирование графика и табеля

**Как** УК, **я хочу** формировать график работы и получать табель из системы, **чтобы** не тратить время на ручную подготовку документов.

**Acceptance criteria:**
- График составляется на месяц с указанием смен, дежурств и отпусков
- Система предупреждает о нарушении норм рабочего времени
- Замена сотрудника оформляется без переформирования всего графика
- Табель формируется на основании графика без ручного заполнения

### US-15. Эффективность сотрудников клуба

**Как** УК, **я хочу** видеть показатели каждого сотрудника, **чтобы** выявлять проблемы раньше, чем они отразятся на результатах клуба.

**Acceptance criteria:**
- По каждому сотруднику отображаются продажи, конверсия и результаты проверок тайных покупателей
- Показатели доступны в динамике за период
- Сотрудники ранжируются по выбранному показателю
- Из карточки сотрудника доступен переход к его операциям

## Руководитель сектора (РС)

### US-16. Сравнительная аналитика по сектору

**Как** РСО, **я хочу** сравнивать клубы сектора между собой, **чтобы** своевременно влиять на показатели.

**Acceptance criteria:**
- Показатели всех клубов сектора отображаются в едином представлении
- Доступна сортировка клубов по любому показателю
- Отображается отклонение показателя клуба от среднего по сектору
- Период сравнения задаётся произвольно

### US-18. Автоматическая выгрузка отчётности

**Как** РСО, **я хочу** выгружать сводную отчётность по сектору в готовом виде, **чтобы** не собирать её вручную для передачи руководству.

**Acceptance criteria:**
- Отчёт формируется по всем клубам сектора за выбранный период
- Состав показателей отчёта настраивается
- Отчёт выгружается в файл в готовом для передачи виде
- Сформированный отчёт сохраняется для повторного обращения


### US-20. Контроль злоупотреблений

**Как** РСО, **я хочу** видеть аномалии по гостевым визитам и пробным тренировкам, **чтобы** выявлять злоупотребления до того, как они станут системными.

**Acceptance criteria:**
- Отображается статистика оформления гостевых визитов и пробных тренировок по клубам и сотрудникам
- Отклонения от средних значений по сектору выделяются
- Доступна детализация до конкретных операций
- Период анализа задаётся произвольно
