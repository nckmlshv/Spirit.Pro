# Требования к системе

## Функциональные требования

| ID | Требование |
|---|---|
| **ФТ-01** | Система должна позволять администратору оформлять новый контракт клиенту, отображая только те тарифы, которые доступны ему по возрасту, статусу и наличию действующих контрактов |
| **ФТ-02** | Система должна позволять администратору создавать карточку нового клиента с заполнением персональных данных и данных документа, удостоверяющего личность |
| **ФТ-03** | В системе должна быть функция отображения администратору скрипта разговора с клиентом по выбранному тарифу и при отклонениях от типового сценария |
| **ФТ-04** | Система должна обеспечивать формирование платёжной ссылки со сроком действия 24 часа и её доставку клиенту по СМС либо в виде QR-кода на печатной форме |
| **ФТ-05** | Система должна обеспечивать автоматическую активацию контракта по наступлению первого из событий: проход клиента через турникет, наступление первого дня следующего месяца, окончание предыдущего контракта |
| **ФТ-06** | Система должна позволять администратору находить клиента по номеру телефона, ФИО, номеру ДУЛ, электронной почте и браслету |
| **ФТ-07** | Система должна предупреждать администратора о вероятных совпадениях с существующими карточками при создании нового клиента |
| **ФТ-08** | Система должна позволять администратору заменять документ, удостоверяющий личность клиента, с сохранением ранее действовавшего в карточке |
| **ФТ-09** | Система должна обеспечивать формирование печатных документов со штрихкодом |
| **ФТ-10** | В системе должна быть функция привязки несовершеннолетнего клиента к карточке законного представителя |
| **ФТ-11** | Система должна обеспечивать автоматическое распознавание штрихкода на отсканированном документе и его привязку к карточке клиента без участия администратора |
| **ФТ-12** | Система должна отображать администратору перечень услуг и предложений, доступных конкретному клиенту, с учётом его тарифа, истории посещений и статуса в программе лояльности |
| **ФТ-13** | Система должна позволять администратору оформлять гостевой визит и бесплатную пробную тренировку с проверкой установленных лимитов и блокировкой операции при их превышении |
| **ФТ-14** | Система должна позволять администратору оформлять заморозку контракта с указанием периода и контролем остатка доступных дней заморозки по тарифу |
| **ФТ-15** | Система должна позволять администратору применять промокоды, подарочные сертификаты и бонусы программы лояльности при оформлении контракта |
| **ФТ-16** | Система должна позволять администратору привязывать контракт клиента к браслету — новому или ранее выданному |
| **ФТ-17** | Система должна позволять сотрудникам регистрировать обращения клиентов и заявки в смежные подразделения с отслеживанием статуса исполнения |
| **ФТ-18** | Система должна отображать администратору историю изменений данных клиента с указанием сотрудника, даты, времени, прежнего и нового значения |
| **ФТ-19** | Система должна позволять управляющему формировать график работы персонала с указанием смен, замен, дежурств и отпусков |
| **ФТ-20** | Система должна отображать управляющим и руководителям секторов аналитику по показателям клуба и группы клубов |

## Нефункциональные требования

| ID | Требование |
|---|---|
| **НФТ-01** | Время отклика системы при открытии карточки клиента не должно превышать 1 секунды для 95% запросов |
| **НФТ-02** | Пользователь должен иметь возможность прервать выполнение операции, не дожидаясь её завершения |
| **НФТ-03** | Доступность системы в часы работы клубов должна составлять не менее 99,9% |
| **НФТ-04** | Отказ одного сервиса не должен приводить к недоступности операций, не зависящих от него |
| **НФТ-05** | Повторная отправка платёжной операции при сбое связи не должна приводить к повторному списанию средств клиента |
| **НФТ-06** | Операция, затрагивающая несколько сервисов, должна завершаться полностью либо откатываться с компенсацией; сохранение промежуточного состояния недопустимо |
| **НФТ-07** | Система должна исключать создание карточек клиентов с идентичным номером ДУЛ или номером телефона |
| **НФТ-08** | Система должна обеспечивать хранение полной истории документов клиента без физического удаления записей |
| **НФТ-09** | Штрихкод, наносимый на печатный документ, должен обеспечивать однозначное сопоставление скана с карточкой клиента и типом документа |
| **НФТ-10** | Доступ к данным должен ограничиваться областью видимости роли: собственный клуб, группа клубов, сектор |
| **НФТ-11** | Персональные данные клиентов должны храниться в зашифрованном виде, все обращения к ним — протоколироваться |
| **НФТ-12** | Система должна обрабатывать пиковую нагрузку в часы с 18:00 до 22:00 без деградации времени отклика |
| **НФТ-13** | Типовая операция должна выполняться новым сотрудником без обращения к внешним инструкциям |
| **НФТ-14** | Каждый бизнес-процесс должен выполняться в рамках одного экрана без переключения между разделами системы |
| **НФТ-15** | Действие в интерфейсе должно выполняться строго в контексте карточки, из которой оно инициировано |
| **НФТ-16** | Интерфейс системы должен сохранять работоспособность на рабочих станциях с разрешением экрана от 1366 пикселей по ширине |
| **НФТ-17** | Система должна вести мониторинг доступности компонентов и уведомлять ответственных о сбоях до обращения пользователей |
| **НФТ-18** | Данные клиентов должны храниться в соответствии с требованиями 152-ФЗ на территории Российской Федерации |
| **НФТ-19** | Восстановление работоспособности системы после критического сбоя не должно превышать 30 минут, максимальный допустимый период потери данных — 5 минут |
| **НФТ-20** | Все интеграции с внешними системами должны выполняться через версионируемые API-контракты с обратной совместимостью |
